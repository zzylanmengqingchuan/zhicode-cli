# 计划制定指南

## 核心原则

- **目标先行**：先明确最终要达成什么，用一句话写清目标，避免"为了做而做"
- **结果可衡量**：每个目标都要有可验证的完成标准（如"跑通 demo"、"读完前 5 章"）
- **拆解到可执行**：步骤要具体到"下一步就能动手"的程度，杜绝"提高能力"这类空泛条目
- **时间盒**：给每个阶段设定截止时间，没有截止时间的计划等于没有计划
- **留缓冲**：排期预留 20% 左右的弹性时间，应对意外和返工

## 计划结构

一份完整的计划应包含以下部分：

1. **目标（Why）**：要解决什么问题、达成什么结果
2. **现状（Where）**：当前处于什么状态、已有什么资源、有什么约束
3. **里程碑（What）**：3~7 个关键节点，每个节点有可验证的交付物
4. **任务拆解（How）**：每个里程碑拆成具体任务，标注优先级和预估耗时
5. **风险与预案**：最可能失败的点是什么，提前准备 Plan B
6. **检查节奏**：多久复盘一次（建议每周），用什么指标判断是否在正轨上

## 输出格式

制定计划时使用如下结构输出：

```
## 目标
一句话描述最终要达成的结果

## 里程碑
1. [里程碑] → 交付物: [可验证的结果] → 截止: [日期]
2. ...

## 任务清单
- [ ] [具体任务]（预估: X 小时，优先级: 高/中/低）
- [ ] ...

## 风险与预案
- 风险: [描述] → 预案: [应对措施]

## 复盘节奏
[什么时候检查进度、用什么指标判断]
```

## 注意事项

- 任务颗粒度：单个任务最好在 0.5~2 天内能完成，太大就继续拆
- 优先级排序：先做的事情应该是"不做就无法推进其他事"的关键路径
- 不要过度规划：远期计划粗一点没关系，近期计划要细
- 计划是活文档：执行中根据实际情况调整，不要把初版计划当圣旨
