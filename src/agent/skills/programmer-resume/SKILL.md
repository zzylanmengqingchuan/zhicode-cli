# 程序员简历撰写指南

## 核心原则

- **一页为主**：工作经验 < 5 年用一页，资深工程师可扩展至两页
- **量化成果**：每条经历尽量附上数据（如"性能提升 40%"、"日活用户 10万+"）
- **针对性定制**：根据目标 JD（职位描述）调整关键词，通过 ATS（简历筛选系统）
- **简洁清晰**：避免花哨设计，使用标准字体（Arial、Calibri），留白充足

## 内容结构

按以下顺序组织简历内容：

1. **基本信息**：姓名、电话、邮箱、城市、GitHub/个人主页（如有）
2. **个人总结**：2~3 句话说清技术栈、年限、最亮眼的成就（可选，资深工程师建议写）
3. **技术栈**：按熟练程度分组列出，如"精通：TypeScript/Node.js"、"熟悉：Go/K8s"
4. **工作经历**：倒序排列，每段经历包含公司、职位、时间、3~5 条成果
5. **项目经历**：挑选最能体现技术深度的 2~3 个项目
6. **教育背景**：学校、专业、学历、时间（应届生可提前到技术栈之前）

## 经历描述公式

每条经历使用"动作 + 技术 + 成果"的句式：

> 通过 [技术手段]，完成 [什么事情]，达成 [可量化的结果]

- 差：负责后端接口开发
- 好：设计并落地订单服务的幂等方案，用 Redis 分布式锁 + 唯一索引，重复下单率降为 0

## 常见错误

- 罗列技术名词但没有任何落地场景（"熟悉 Spring Cloud"不如不写）
- 只写职责不写成果（"负责 xx 系统" ≠ 做出了什么）
- 精通一大堆技术栈，面试一问就穿帮，不如诚实分级
- 使用"参与"、"协助"等弱动词开头，改用"主导"、"设计"、"落地"、"优化"
- 页数过多、排版花哨、有错别字——任何一条都可能直接被刷掉

## 输出要求

- 帮用户写或改简历时，先问清目标岗位和工作年限，再动手
- 技术栈描述要与目标 JD 的关键词对齐，但不得虚构用户不会的技术
- 所有量化数据必须来自用户提供的信息，不得编造数字
